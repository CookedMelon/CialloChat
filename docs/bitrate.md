# 2K 屏幕推流与流量预算

本实例按 2560×1440、视频 **3200 Kbps** 配置。OBS 选择 H.264、CBR、AAC 128 Kbps、关键帧 1 秒、B 帧 0。屏幕分享优先 30 fps；60 fps 在相同码率下会分摊每帧预算，动态画面和细小文字可能更模糊。服务端只转发，不调整编码码率。

## 平均码率断连

默认每路发布上限 **4000 Kbps**。视频 3200 + 音频 128 = 3328 Kbps，再留约 20% 的封装和波动余量。音频 160 Kbps 也在此预算内。实际编码器峰值须用真实屏幕验收。

watchdog 每秒读取 MediaMTX 累计 `inboundBytes`，计算约 5 秒平均值；窗口满后连续两次大于上限即主动断开发布连接。覆盖 RTMP、RTMPS、RTSP 发布。正常持续超限约 6–7 秒后断开，故障期间不能保证该时限。这是平均码率检测，不是逐包硬限速；重连重新积累速率窗口，但不会重置密码期限。

```bash
./streamctl limits
./streamctl limits --publish-kbps 4000
```

值持久保存，运行中可调整。新实例和没有该字段的旧设置默认 4000；已有显式旧上限需执行上述命令更新。两小时过期和邮件见 [密码期限](publisher-lifetime.md)。

## 出站流量

十进制计算：3200 Kbps 视频每小时约 1.44 GB；加 AAC 128 Kbps 后每名观众每小时约 **1.50 GB**、两小时约 **3.00 GB**，还需预留协议开销和重传。五名观众观看两小时约 15 GB。每名观众收到一份流，不能只按一次推流计费。4000 Kbps 对应每名观众两小时约 3.6 GB 媒体连接数据，但检测窗口、重连和网络开销使它不能成为严格账单上限。

阿里云 ECS 公网按流量计费通常只收公网出站费用，入站免费。服务器下载依赖、客户端推流是入站；观看转发、SSH 下载、TCP 响应是出站。如使用 EIP、共享流量包等产品，需检查对应账单。[阿里云带宽计费说明](https://www.alibabacloud.com/help/en/ecs/user-guide/network-bandwidth)

本项目没有总 GB 预算；当前缓冲入口最多允许八个同时观看连接。可在云控制台设置公网出站带宽上限和费用预警；严格流量预算还需计费周期总出站额度控制。

## 停播、错误密码与垃圾数据

当前关闭录制、HLS、WebRTC 和 `alwaysAvailable`。停播后不再生成或循环视频；媒体源消失时观看连接被关闭。播放器自动重试仍有少量 RTSP 请求、响应和 TCP 数据，不是持续 3200 Kbps 的媒体流。黑屏但 OBS 仍在推流也会产生媒体流量。

MediaMTX 在发布准入成功前校验密码；正常 OBS 错误密码被拒绝并关闭，不能持续发布大段媒体。鉴权服务限制请求体 16 KiB、并发校验数和每 IP/动作失败次数（60 秒内五次失败后拒绝新的哈希校验，近期已验证成功的缓存凭据仍可用），发布鉴权不接收媒体；完整服务的观看媒体经过有界的 Python RTSP 缓冲入口。同一 NAT 下的客户端可能共同受到失败限制，修正密码后最多等待该窗口结束。

错误密码不意味着零网络流量：握手、TLS、拒绝响应和重连仍有少量流量。攻击者还可在鉴权之前发送垃圾字节；已到达服务器的数据不能靠应用鉴权撤销。宿主机入口限连接减小握手开销，云安全组白名单和云防护处理扫描与洪泛。速率检测只覆盖成功发布者，不覆盖所有未鉴权 TCP 字节。[MediaMTX 1.21.1 发布鉴权顺序](https://github.com/bluenviron/mediamtx/blob/v1.21.1/internal/servers/rtmp/conn.go)
