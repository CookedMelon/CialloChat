# 常驻推流测试频道

本地：`rtsp://172.23.64.247:8554/test`。正式部署：`rtsp://chat.v50to.cc:8554/test`。直接在 VRC 直播播放器或 VLC 中打开，无需账号密码。

唯一视频文件为十分钟预编码 MP4：2560×1440、60 fps、libx264 H.264、CBR 1600 Kbps、每秒关键帧、单切片、无 B 帧，AAC 128 Kbps / 48 kHz 双声道。画面含逐帧编号、四行连续滚动文字及断连倒计时，声音连续变调。

## 限时规则

- 每个真实来源 IP 从首次请求取得配额起开启十分钟窗口，短暂断线或重连仍使用该窗口，不能刷新倒计时。
- 十分钟窗口结束后冷却五分钟。即使在窗口中提前断开，也不能通过重新连接跳过该窗口的结束与冷却。
- 每 IP 每个北京时间自然日最多占用连接六十分钟；断开后的空闲时间不累计。剩余日额度不足十分钟时，缩短本次连接和画面倒计时。
- 同一 IP 同时只允许一个测试连接；同一 NAT 出口共享额度。全部缓冲连接合计仍最多八个。
- 配额、冷却和时间高水位持久保存在 `runtime/test-video/quota.sqlite3`，重启不清空。异常重启保守累计此前窗口至重启/到期，以避免退款绕过期限。

倒计时烧录在视频中，按剩余额度选择播放起点，补偿服务端的一秒缓冲；实际播放器额外缓存会使所见数字与服务器断连存在少量差异。普通直播账号的累计两小时推流额度与测试频道互相独立。

## 部署

```bash
# 一次生成；保留既有素材即可，不需要每次升级重建或上传
.venv/bin/python scripts/build-test-video.py
# runtime/settings.json 启用 test_video_enabled=true；需要 systemd 和 rtsp_buffer_ms=1000
./streamctl down
./streamctl apply
./streamctl up
```

若已有业务推流，选择维护窗口再执行 down/up。生成文件约 130 MB，保存在私有 runtime 中，不进入 Git 或源码包。生成阶段需要 libx264 和字体；播放阶段仅 FFmpeg 复制码流，不进行实时转码。FFmpeg 可以来自系统安装或本地已提取的工具目录。

测试入口长期随缓冲服务运行；无人观看时不启动文件发布进程，不发送测试媒体。每个获准 IP 按需启动一个低 CPU 的码流复制进程，断连时回收；内部 `test/<随机令牌>` 不对外公开。测试播放使用与普通直播相同的一秒 RTSP 缓冲策略，并在流量报告中合计到 `__test__`。

测试素材暂缺时不阻止普通直播启动，测试请求直接关闭且不占用配额。完整素材校验并原子安装后，测试入口自动可用，不需要重启业务服务。
