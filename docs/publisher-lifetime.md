# 两小时推流密码与续期邮件

每个推流密码有 **7200 秒累计推流额度**。watchdog 每秒查询 MediaMTX 的实际发布连接，仅推流占用时间计入；鉴权成功但未发布、仅观看和停推空闲均不消耗额度。短暂断线后继续累计，服务重启不重置已用额度。额度耗尽后旧密码永久拒绝，watchdog 主动终止已有发布连接。观看密钥独立，不轮换。同一用户同时存在多个发布连接时按连接时间的并集计时，不重复扣减。

例如：推流 30 分钟、停止一整天、再推流 30 分钟，此时仍剩 60 分钟。创建账号或手动刷新推流密码不会开始一个随空闲时间流逝的两小时倒计时。

使用量保存在 `runtime/leases/leases.sqlite3`，权限 600。计量使用单调时钟与服务器启动标识，不受系统日期调整影响；普通断线计量精度约一秒。连续发布连接跨 watchdog 重启时继续累计；旧连接已消失且无法确定中断时刻时，仅保守计入最多五秒的末尾采样区间。服务器重启后的停机时间不计入，已经消耗的额度保留。

只有**正在推流且剩余使用额度不超过十分钟**时，后台才生成下一密码并发送续期邮件。每一代成功发送一次，停推时不触发自动通知，失败通知的自动重试也暂停。成功发信后新密码可用；收到但未使用的新密码不消耗额度。提前使用新密码立即作废上一密码并踢掉上一代连接，新的两小时额度从实际推流开始消耗。没有手动替换 URL 的 OBS 自动重连始终使用旧密码，不能自动续期。

SMTP 故障不会延期旧密码，也不会阻塞断连线程。正在推流时，失败至少间隔 60 秒重试相同密码；重启保留待发送状态。如果额度已经耗尽仍未成功发信，需要管理员刷新推流密码。SMTP 超时结果不明确时邮件可能重复，重试使用相同密码和 Message-ID。成功发送后的明文凭据保留在权限 600 的私有租约库，手动使用时同步当前凭据；不写密码日志。创建、手动刷新与自动续期通知均使用同一简洁模板，见 [远程控制](remote-control.md)。创建和管理员手动刷新属于主动操作，仍立即发送邮件。

旧版数据库升级时，保留升级时的剩余额度，随后切换到累计推流计时；已经过期的旧密码不会恢复。旧版没有记录完整推流时段，不能准确退款历史空闲时间，需要恢复全额时由管理员手动刷新密码。

## 填写发信配置

发送邮件使用 SMTP；POP3 / IMAP 是收信协议。邮箱后台可能需开启“POP3/SMTP”获取授权码，但本服务仅使用 SMTP。优先填写 SMTP 授权码，不使用网页登录密码。

填写文件为 `config/smtp.json`，本地部署时安装至 `runtime/notifications/smtp.json`，公开样例为 [SMTP 样例](../config/smtp.example.json)。

也支持 `config/smtp.json` 中的 `smtp_host`、`smtp_port`、`smtp_ssl`：true 使用隐式 TLS，false 使用 STARTTLS，均不允许明文登录。`pop3_host`、`pop3_port` 可保留，但不用于发信。私有 `config/smtp.json` 已排除出 Git 和源码交付包，文件权限保持 600。

| 字段 | 含义 |
| --- | --- |
| host | 邮箱提供的 SMTP 主机 |
| port | 通常 465 或 587，以提供方为准 |
| security | 465 通常 `ssl`；587 通常 `starttls`；只允许 TLS |
| username | SMTP 登录账号 |
| password | SMTP 授权码 |
| from | 发件邮箱 |
| recipients | 用户名到接收邮箱映射，按实际账号名填写 |

填好后安装为实际配置：

```bash
chmod 600 config/smtp.json
./streamctl mail configure config/smtp.json
./streamctl mail status
./streamctl sessions
```

`mail configure` 不发送测试邮件。后台约五秒内读取配置，临近到期时发送。未配置邮箱的用户仍会过期，届时可请管理员重置推流密钥。发信网络须能访问 SMTP 端口。

## 人工恢复与备份

```bash
./streamctl user reset-publish-key alice
```

新凭据获得完整两小时累计推流额度，实际推流才消耗。禁用/删除账号或管理员重置后，旧代及该代待发续期密码不能继续使用。`sessions` 输出已用秒数、剩余秒数、在线推流及发送状态，不输出密码。

自动轮换密码保存在租约数据库，账号文件保留管理员最近设置的基础哈希，旧基础密码不会因账号文件没改而重新有效。`user credentials` 只针对管理员配置的基础密钥；轮换 URL 以收到的邮件为准。

迁移/灾备应在停服时一并备份 `runtime/leases`；普通 `streamctl backup` 保存账号设置，不包含此数据库。不要删除租约库或用过时副本恢复它，否则可能重新接受账号文件中的旧基础密码。正常重启、账号 enable 和配置 apply 不删除租约。备份保持管理员专用。
